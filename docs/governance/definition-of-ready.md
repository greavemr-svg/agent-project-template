# Definition of Ready

Work is ready to design when a developer and a tester could each work from the
spec without asking anyone a question.

- [ ] One clear problem statement and the user it's for
- [ ] Acceptance criteria numbered AC1…ACn, each in Given / When / Then form
- [ ] Each AC is testable by an automated test, or explicitly marked `manual` with how to check it
- [ ] Out of scope is written down
- [ ] Non-functional requirements stated (performance, accessibility, security, offline behaviour), or "none beyond project defaults"
- [ ] Data and privacy impact stated: what personal data is created, stored, shown or sent, and where
- [ ] Assumptions listed as assumptions
- [ ] Dependencies on other work, services or accounts listed
- [ ] No TBD, TODO or open questions
- [ ] Small enough for at most 8 tasks; otherwise split into more than one idea
